# Interpretation of the controlled comparison

The user selected the original lifted-product paper, not the later bias-tailored paper. Only the explicit [[1054,140]] Example4 is run. Its distance remains unverified; the paper's unsuccessful search below weight20 is not a certified lower bound. There is no source LER curve or error-rate grid for this example.

The32-sweep/.625 baseline is borrowed from the cited BP-OSD paper. Its layered schedule differs from the canonical flooding schedule used here. Binary arms have at most32 sweeps on each component and joint arms have32 sweeps on the combined graph: their maximum directed edge updates are equal. Search128 deliberately permits four times that cumulative component budget; Search32 stays within the baseline work ceiling. Fewer actual sweeps, early convergence and masked edges are measured, not replaced with the ceiling.

Latency is **instrumented end-to-end decoder latency**. The frozen traversal timer includes posterior digest construction and, for search, all-state posterior/message digest construction and lineage extraction. It excludes sampling, outcome evaluation, JSON serialization, ledger writes, graph preparation and JIT. These timings must not be described as pure kernel time or an instrumentation-free algorithmic speedup. LER, total sweeps, directed edge updates, OSD candidate operations and these instrumented latencies remain available separately. A future pure-decoder timing study requires a new frozen protocol; these measurements must not be silently relabeled.

Confirmation is independent of both tuning stages. All tested numerical and search settings remain in their own ledgers; concrete selected settings can differ between rates. A displayed curve still requires two distinct measured physical rates with compatible exact settings. No aggregation of unlike settings is permitted to make an arm visible.

Scheduler receipt `dependency-release.json` records a scheduling-only repair. Slurm held later audit-array tasks behind an unfinished earlier index despite successful corresponding simulation tasks. Only tasks with an existing matching completion receipt and accounting state COMPLETED0:0 were released. The unchanged frozen auditor still performs the full ledger, independent outcome/work, selection and endpoint checks. Unfinished source points retain their original dependencies and stopping rules.
