# Resource amendment: ten CPUs per remaining point

The user requested ten processors per remaining point on2026-11-17. This supersedes the execution allocation only. The original `plan.json`, frozen source, circuits, seeded sample bytes, global-shot random policy, stopping and identities remain unchanged. Original completed points and committed prefixes are preserved. `resource-amendment.json` separately pins the new controller and qualification.

`parallel.py` uses ten spawned single-thread process workers in a ten-CPU Slurm allocation. A lightweight parent coordinates tasks and I/O within that allocation. Independent source batches run concurrently across X/Z memory bases. Results enter the canonical ledger strictly in each basis's original global-shot order. The first20th observable error or100M-shot prefix remains exact, regardless of task completion order. Bias/random lineage, candidate, prediction and all-path work are the frozen decoder outputs. Child resolved DEM execution hashes must match the parent's bytes. JIT warmup precedes measured calls.

Each child seals its entire computed batch, retaining candidate/prediction/work/timing/trace arrays and the original sample binding. The parent hardlinks a fully retained batch into the original ledger format or writes the precisely trimmed prefix. All speculative batches and beyond-stop work remain in `parallel-stages/`, and `parallel-work.json` separates computed, retained and speculative work. Speculation never enters the figure denominator, LER or retained-shot work means. Interrupted computations before a sealed stage have unmeasured cost; no full attempt-level work claim is made.

Resume begins with parallel independent revalidation of every committed original-DEM candidate, path-work trace and chunk endpoint. `inherited-prefix.json` records the exact inherited marker hashes and summaries. The original manifest/hardware and all old canonical chunks remain intact. Full audits run in a fresh interpreter with another ten-process pool, reevaluating every canonical event and all sealed speculative events, replaying endpoints and reconciling exact stopping and work. The resulting `complete.json`/`audit.json` remain compatible with the original frozen publisher.

Per-shot decoder times remain recorded with their original scope. Concurrent ten-CPU hardware/cohort metadata is saved separately. Pooled old/new means are not standalone one-CPU latency comparisons; splitting timing by resource cohort is required for such analysis. Statistical LER/work identity is independent of this resource history.

The qualification uses separate seeds and three full-paper-budget cases (BB144 PriorTilt, BB70 Relay, GB102 Beam), with80 shots per memory basis and inherited original chunks. All candidate/prediction/stat/trace arrays must exactly match sequential execution, fresh full audits pass, and resume leaves receipts unchanged. Qualification shots never enter production. Thread-based small-fixture tests separately check scheduling, exact target trimming, sealed reuse and stage work accounting.

Deployment first submits ten-CPU/24GiB replacement jobs and a new after-success collector, then cancels only the superseded live one-CPU tasks and pending collector. New jobs depend on termination of the original array, preventing concurrent owners of a point. The point lock adds an independent guard. Only uncommitted in-flight work may be regenerated. SIGUSR1 checkpoints kill the process group and requeue the same task; committed and sealed-stage files survive. Free-space protection is retained.

Use `parallel_control.py freeze` then `parallel_control.py submit`. Production worker is `parallel-worker.sh`. Use **`parallel_report.py`** for subsequent report refreshes: it runs the unchanged statistical publisher and adds the resource history; the original publisher's one-CPU prose describes the original allocation. No public catalog or archived interface is changed by this amendment.
