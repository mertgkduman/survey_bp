# Implementation research

Primary source: [pinned native OSD](https://github.com/quantumgizmos/ldpc/blob/d3429964cd4ffe1abfc041c6ec8b8425cb174f40/src_cpp/osd.hpp).
Fetched source blob e4f895c345de25ca5e2289572de09d93da39145b. Source factors
once, enumerates all free singles then pairs in the requested prefix, repeatedly
solves modified syndromes, scores `log(1/p_i)` in original column order, and
updates the winner only for strict improvement. Nonuniform source scoring is
not identical to Bernoulli maximum likelihood; explicitly name both.

Affine response reuse removes repeated solves without changing the search.
Packing changes arithmetic/storage, not the code's candidate family. Sparse
original H can be retained without dense allocation, but elimination fill-in
favors packed rows. A basis cache needs the complete row transformation to
apply a different syndrome and an exact ordering key; changing reliability
orders can make hit rates negligible. Measure hit/miss overhead rather than
assuming a production gain.

Streaming SHA256 must receive all candidate bytes before any weight bytes,
matching v1 on uniform inputs. Retain O(candidate count) scores until hashing;
avoid O(candidate count * packed width) pair storage. Peak RSS includes the
interpreter/JIT; also measure traced incremental decode memory and cold setup.
