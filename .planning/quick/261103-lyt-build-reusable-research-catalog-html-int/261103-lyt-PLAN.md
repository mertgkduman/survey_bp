# Reusable research interface and portable experiment packages

Implement the user's supplied product requirements through the GSD quick
workflow as an independent product slice. Existing scientific phases and
qualification gates keep their current status. No expensive campaigns or remote
deployment are in scope.

1. Inspect public study/CLI execution, decoder compatibility and numerics,
   canonical/compiled kernels, independent evaluation, circuit integration, and
   retained studies. Record API and evidence findings before choosing adapters.
2. Define a versioned catalog linking papers/local studies, reusable decoder
   specifications, codes, circuits/channels, experiments, and actual datasets.
   Populate it from retained evidence without relocating or rewriting it.
3. Implement shared configuration validation and portable package execution over
   the existing kernels/evaluators. Support registered/custom codes and Stim
   circuits, effective settings, immutable run outputs, implementation identity,
   sampling controls, ledgers, summaries, and analysis. Validate exact matches to
   existing configurations before offering existing results.
4. Build a lightweight repository-hostable responsive HTML interface consuming
   the shared catalog/contracts: browse, real plots/tables, inspect/export
   specifications, configure code-capacity/circuit experiments, and download
   packages. Simulations execute locally after download. Raw-data links must
   reflect actual availability.
5. Verify exports with bounded fixtures in an isolated environment; exercise the
   eight requested browser workflows, mobile/desktop and keyboard use. Review
   compatibility, provenance, evidence labeling, and output preservation.
6. Document local preview, installation, catalog extension, and validation
   limitations; update GSD state and commit the verified implementation.

Specialists may inspect and implement independent owned modules in parallel as
explicitly authorized by the user. They must not revert other contributors'
changes. Preserve configured role models, v1/v2 identities, resolution policies,
existing evidence, and canonical family boundaries.
