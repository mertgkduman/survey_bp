# PriorTilt checks H internally; released Sinter workflow scores observables only

The current public PriorTilt Rust core, Python wrapper, Sinter adapter and simulation helper match the corresponding git blobs at the campaign's pinned author commit `8eefd37d694b5942fe60ec6d5c82ce97f3d2a450`. All four current-main files were inspected through the GitHub connector. `probe.json` records the verified blob IDs and native binary hash.

1. **Internal syndrome stopping is implemented.** Each BP iteration constructs the estimated detector syndrome by XOR-ing the detector supports of the hard-decision error bits. It compares `cand_syn` against the supplied syndrome, sets `converged=true` and returns on equality. See [Rust lines302–326](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/decoder/src/lib.rs#L302-L326).
2. **Budget exhaustion returns an estimate even without convergence.** Decode resets convergence tofalse, returns early on a valid syndrome, and returns the final hard-decision vector after exhausting the loop. The `converge` getter exposes the flag. Native batch decode returns only error vectors, not a vector of convergence flags. See [decode lines368–407](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/decoder/src/lib.rs#L368-L407) and [batch/getter lines448–507](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/decoder/src/lib.rs#L448-L507).
3. **The Python wrapper projects every returned estimate onto observables.** Both single and batch methods compute the observable-matrix product modulo2 without conditioning on `converged`. See [Python lines276–303](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/priortilt/__init__.py#L276-L303).
4. **Sinter receives only those predicted bits.** The compiled adapter delegates to `decode_batch` with bit packing, and the file adapter writes only observable predictions. No convergence flag, forced-error marker or convergence-based discard is passed. The released task construction supplies no syndrome/convergence postselection. See [adapter lines39–46](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/priortilt/sinter_priortilt.py#L39-L46), [file adapter lines93–97](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/priortilt/sinter_priortilt.py#L93-L97) and [simulation lines324–340](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/simulation_functions.py#L324-L340).
5. **The counter is observable disagreement.** Sinter compares predicted and sampled observables by XOR and flags any differing bit. The author timing helper independently uses the same observable-only comparison. See [official Sinter implementation](https://github.com/quantumlib/Stim/blob/main/glue/sample/src/sinter/_decoding/_decoding.py) and [author helper lines431–435](https://github.com/ionq-publications/PriorTiltDecoder/blob/8eefd37d694b5942fe60ec6d5c82ce97f3d2a450/simulation_functions.py#L431-L435). Installed Sinter1.15.0 and current upstream have different file blobs but agree on this predicate.

Consequently the released workflow measures `P(A ehat != A e)`. The literal joint criterion in the quoted paper statement would measure `P(H ehat != s OR A ehat != A e)`. Their difference is exactly `P(H ehat != s AND A ehat = A e)`. A nonconverged estimate can therefore count as a correct observable prediction. Sinter's circuit-memory observable-prediction task and the quoted valid-error-vector recovery criterion are distinct definitions.

## Executable native/wrapper counterexample

`probe.py` executes the unmodified author native decoder, Python wrapper and actual Sinter compiled adapter on a valid synthetic detector error model. Four independent0.1-probability mechanisms have distinct detector supports, so the author's detector-support merging shortcut is irrelevant. The reachable actual error is `[1,1,0,0]`, giving syndrome `[1,1,0]` and observable `[1]`. After two zero-offset sweeps, the author decoder returns `[1,1,1,1]`: estimated syndrome `[0,0,0]`, `converged=false`, but observable `[1]`. Both single and packed batch adapters return that correct observable prediction. The standard XOR scoring rule marks no observable error, whereas the two-equation definition fails. All assertions pass. This is an intentionally short-budget semantic example, not a paper-budget LER experiment.

## Consequences for our reproduction

Our frozen campaign explicitly reproduces observable-only scoring and independently records syndrome convergence. Its four joint counters are: valid/observable-correct, valid/observable-wrong, invalid/observable-correct, invalid/observable-wrong. An existing completed canonical example is BB144/p=.002 Z-memory:1,192,846 shots,20 observable failures, plus one nonconverged observable-correct shot. The joint criterion gives21 failures on that same recorded prefix. These are our canonical adaptation's counts, not the authors' hidden historical convergence statistics.

Per-shot records allow the stricter criterion and its earlier stopping prefix to be reconstructed separately without resimulating. No running campaign, failure predicate, target, frozen/source files, kernels or current report was changed in this investigation. Published author CSVs supply errors/shots/discards, not convergence or the four-way contingency counts; those files alone do not recover the authors' joint-criterion rate. The released source establishes present public workflow behavior, not every detail of unpublished historical figure-generation code. Agreement of curves cannot resolve this distinction by itself.
