# Focused research interface v2

The primary `/web/research/` route is now v2. The shipped v1 HTML/CSS/JS,
catalog, contract, ZIP writer and package template remain at `/web/research/v1/`.
An archive label/backlink and the extra repository-relative asset path are the
only archival UI adaptations; an archive manifest records original/current bytes.
Catalog rebuilds do not overwrite the archive.

## User-facing changes

- Exact requested branding and workflow-first navigation: Getting started,
  Available experiment results, Experiment builder, Version difference and
  Recommendations, and Policies. Removed Papers from v2 navigation.
- Workflow instructions and real commands under all four steps, including where
  downloaded experiment files go and how to import generated outputs.
- Results use only Code/circuit and Decoder selectors, with independent added
  side-by-side plot cards, Show curves, the requested twelve-column table, CSV
  exports, run settings, reproduction actions and expandable provenance.
  Published source transcriptions and unmeasured coordinates are excluded from
  v2, while the original catalog and v1 preserve them. Weighted/low-count/pilot
  evidence retains its own labels and uncertainty semantics.
- Noninteractive policy and code-family lists, exact-circuit availability, and
  empty-family representation. No BB144 fixture is presented as a BB72 circuit.
- Decoder builder and code/circuit input columns, simulation controls underneath,
  parity-check JSON and Stim inputs, saved specifications and explicit unsupported
  combinations. Advanced numerics/full JSON are expandable.
- Policy equations render locally with vendored, licensed KaTeX; named methods
  link to primary papers and distinguish custom-builder/study/circuit support.
- Removed v1 material and future recommendations are explicitly separated in
  the requested version/recommendations page.

## Execution and evidence

The existing canonical/compiled kernels and independent evaluators are reused.
Optional failure/Type-I/Type-II sampling targets stop each rate at its first
boundary or shot cap. Frozen three-key sampling specs retain fixed-N behavior.
Circuit targets concern observable failures; Type I/II controls are rejected.
Adaptive results retain actual denominators and omit fixed-N confidence claims.

New output includes a derived catalog entry. Python validates identities,
provenance, effective settings, streamed ledgers, canonical summaries and CSVs
before metadata-only repository import. Browser import reconstructs its own entry
from all manifest-bound files and ignores unbound catalog metadata. It verifies
counts/rates/CI/methods/work/stopping/identities and persists only locally; the CLI
registers metadata under research/imported without copying raw ledgers. Inputs
are content-addressed, while decoder/run identities distinguish different runs.
