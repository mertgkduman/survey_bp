# Phase 6 candidate-list selection foundation

Implement a small project-owned selection primitive for CSS candidate lists. It must retain each candidate's origin, declared eligibility, score, and rejection reason; independently check the original syndrome; and select with an explicit score and deterministic tie rule. This is generic infrastructure for Phase 6, not a claim that it implements BeamSearch or a voting rule.

## Tasks

1. Define strict immutable candidate, policy, assessment, and result records in a new canonical module. Keep arrival order irrelevant and never expose hidden simulation truth.
2. Implement original-problem syndrome validation, declared scoring, and stable selection. Preserve rejected candidates and selected candidate lineage and bits in evidence.
3. Add small-code tests for invalid original candidates, unavailable/ineligible candidates, score ties, arrival-order independence, and malformed input.
4. Run focused tests, commit the isolated Phase 6 foundation, and record status without altering the running Phase 5 source seal.
