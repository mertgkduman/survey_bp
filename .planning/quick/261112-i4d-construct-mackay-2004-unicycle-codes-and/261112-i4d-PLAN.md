# MacKay 2004 unicycle BP campaign

Use the GSD quick research and validation workflow inline. Read AGENTS.md,
STATE.md, PROJECT.md and the active Phase 11 plan; retain the existing phase.

1. Pin quant-ph/0304161v3 and qualify Construction U at lengths 74 and 274.
   Use the explicit published length-73 difference set and a deterministic
   perfect difference set for length 273. Record the latter's ordering as a
   project convention. Verify difference multiplicities, CSS commutation,
   ranks and paired logicals; freeze portable input artifacts.
2. Reuse the canonical sum-product kernels for ordinary binary BP, the paper's
   two hypotheses for the extra unicycle bit with likelihood selection, and
   joint Q-BP. No new execution engine. Use X-only rates .04 through .10 and
   depolarizing rates 1.5 times these. Preserve float64, p0=p, Q-BP d=.1 and
   no check cap. Resolve the optional iteration-ceiling question before freeze.
3. Freeze settings, code identities, software and runner hashes before sampling.
   Retain a contiguous iid prefix ending at 20 block failures or 100 million
   shots; record Type I/II independently, all branch work, runtime, input and
   candidate hashes, compressed resumable ledgers and exact stopping intervals.
4. Validate construction, branch likelihood selection, >63 logical qubits,
   work accounting, deterministic replay, checkpoint resume and plan integrity.
   Submit the frozen grid through Slurm and audit retained terminal evidence.
5. Emit the existing normalized catalog-extension format. Preserve the central
   multi-rate visibility filter. Check registered-input selection, results,
   work columns, exports and empty states in Chromium. Update GSD and commit.

Published code-family and decoder mechanisms do not establish a paper-curve
reproduction: this is a controlled campaign with new noise/budget settings.
The paper's independent-X/Z channel and its classical block-error plots must
not be confused with our X-only or joint quantum block-failure measurements.
