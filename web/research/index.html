Getting started

View results here. Reproduce them or run a new experiment on your machine.

1

Browse available experiment results, supported policies, and saved decoders.

Open results to compare curves, or inspect policy equations.

# In an existing checkout, list registered results and decoder specifications.
bp-registry-research list datasets
bp-registry-research list decoders
2

Inspect or adapt an exact BP-based decoder specification. Choose a code or circuit.

Start from a saved specification in the experiment builder. Unsupported combinations remain visible as validation errors.

# After downloading experiment.json, keep it in a new experiment directory.
# Once step 3 is installed, validate this exact file before running.
/path/to/survey_bp/.venv/bin/bp-registry-research validate ./experiment.json
3

Clone and install the repository. Download the experiment package or JSON file. Run the generated experiment.

git clone git@github.com:mertgkduman/survey_bp.git
cd survey_bp
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[performance,circuit,analysis]'
# Open the workbench locally.
.venv/bin/python -m bp_registry.research.cli serve --port 8765
Where to put the download and how to run it
# Keep downloaded experiments outside the source checkout, each in its own folder.
mkdir -p ~/bp-experiments/run-001
cd ~/bp-experiments/run-001
# Move the downloaded ZIP here, then extract its contents into this folder.
# Replace the filename with the ZIP you downloaded.
unzip ~/Downloads/my-bp-experiment.zip
# Replace /path/to/survey_bp with the absolute path of your checkout.
/path/to/survey_bp/.venv/bin/python run.py --repo /path/to/survey_bp --validate-only
/path/to/survey_bp/.venv/bin/python run.py --repo /path/to/survey_bp --output ./results
/path/to/survey_bp/.venv/bin/python analyse.py ./results
# If you downloaded only experiment.json, the CLI runs that same specification.
/path/to/survey_bp/.venv/bin/bp-registry-research run ./experiment.json --output ./results-json
4

Upload the generated results to add them to the results database.

Select the output files together below. Validated results are saved in this browser and appear in Available experiment results. To share them through the repository, use the import command.

# Use the results directory produced in step 3. This adds a catalog entry;
# raw ledgers stay at their original storage location.
/path/to/survey_bp/.venv/bin/bp-registry-research import-results ./results
# Rebuild the shared result index and refresh the browser.
cd /path/to/survey_bp
.venv/bin/python -m bp_registry.research.cli build

Version difference and Recommendations


1. What moved out of the main workflow
  • Paper, experiment, and dataset selectors: retained in the v1 archive. V2 selects code/circuit and a saved decoder; run details remain attached to every curve.
  • Published source transcriptions: kept in the source catalog and v1, excluded from v2 measured curves.
  • Full provenance, confidence methods, sampling cohorts, and raw-data availability: available under each plot’s run details and in exported receipts.
  • Study-specific Relay, Beam, memory, and degeneracy policies: retained in registered workflows. The builder explains compatibility rather than replacing them with plain BP.
  • Advanced numerical controls and complete JSON: moved into expandable sections.
  • Exact historical identities and ledgers: preserved in their original directories.
2. Further recommendations
  • Add a shared review queue for uploaded results, with server-side hash and ledger verification before publication. This MVP stores browser imports locally; the CLI persists them to the repository index.
  • Keep matrix representation and code equivalence separate; support multiple named check representations per code family.
  • Use a common policy editor as more interventions become qualified for the portable runner.
  • Add paired rescue/loss comparisons, anytime-valid confidence intervals for adaptive sampling, and benchmark machine profiles.
  • Offer shared axes and saved comparison layouts for multi-plot analysis.
  • Expand circuit-policy qualification and retain detector/observable semantics.
